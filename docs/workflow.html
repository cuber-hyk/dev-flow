Workflow

从模糊需求到可审核合并

Dev Flow 把任务拆成一组 gate。每个 gate 都有明确职责，避免 AI 跳过决策、混入无关改动或把一次性报告当成长期知识。

日常开发 步骤输出 审查驱动 分支闭环 审核输出

日常开发：brainstorm -> plan -> branch

模糊需求先由 /dev-brainstorm 澄清目标、非目标、方案和决策；明确任务由 /dev-plan 创建计划；/dev-branch 负责实现、验证和审核前收尾。

Brainstorm
/dev-brainstorm->Intent Gate->Confirmed route
Plan
/dev-plan->Orient Gate->Decision Gate->Plan file or chat plan
Build
/dev-branch->Task branch->Implement->Verify
Close
Changelog Gate->Distill Gate->Check Gate->Review Gate->Approve

每一步最后输出什么

Dev Flow 的重点不是多跑几个命令，而是让每个阶段留下可审查的结果。用户可以从输出判断下一步是否能继续，Agent 也能从产物继续接力。

阶段内部经历最终输出可继续条件
/dev-orient读取 AGENTS、CONTEXT、context-map、相关 capability 和代码入口。上下文来源、相关入口、文档目的地、推荐下一技能。事实源明确，下一步路由清楚。
/dev-brainstorm低噪声进入上下文、澄清目标/非目标、比较方案、确认用户决策。confirmed route、decision points、alternatives、下一技能。目标和关键决策已确认，或明确停下提问。
/dev-planOrient Gate、Decision Gate、范围确认、步骤和验证设计。目标、范围、事实源、步骤表、验收标准、plan 路径或 blocked 原因。没有未决决策，步骤都有验证方式。
/dev-auditAudit scope、证据读取、finding 编号、严重度和状态判定。带 ID/Status/Evidence/Owner Plan/Verification 的 findings，必要时写入 docs/audits/。每个 finding 有证据和后续路由。
/dev-branch创建分支、实现、验证、Changelog Gate、Distill Gate、Check Gate、Review Gate。变更摘要、验证结果、三个 gate 结果、git status/diff、等待审批说明。所有必要 gate 通过或明确不需要。
/dev-distill知识分类、ADR Gate、plan closeout、audit closeout、验证。长期文档更新、plan/audit 生命周期结果、ADR 判断、下一步 check。未关闭产物保持 active；可关闭产物有明确原因。
/dev-check检查模板、文档路由、状态字段、归档目录和 git 可见性。errors、warnings、recommendations、validation result。无 error；warning 有明确处理或接受理由。

审查驱动：audit -> plan -> branch

当任务是“看看哪里不对”时，先审查，不要直接写计划。审查报告只放在 docs/audits/，稳定事实由后续 distill gate 同步到长期文档。

1
/dev-audit

内置 orient gate，定义范围、读取证据、输出带 ID 和状态的 findings。非平凡审查写入 docs/audits/。

2
/dev-plan

把确认后的发现转成单一路线计划，并记录 source_audit、covered_findings 和 deferred_findings。

3
/dev-branch

实现修复，在审核前更新 finding 状态、验证结果和 branch/commit 关联；未全部关闭的 audit 继续保持 active。

分支闭环：同一次任务只做一个可解释 diff

/dev-branch skill 不要求工作区绝对干净，但要求改动可归属。相关 plan/audit 可以带入任务分支，无关源码或配置改动必须先停下询问。

Changelog Gate

影响用户、操作者、公开行为、数据、安全、安装、配置、兼容性或发布说明时，更新 CHANGELOG.md。

Distill Gate

任务改变长期知识、ADR、context-map、测试或 plan/audit 生命周期时，在审核前一起处理；部分修复只能更新 finding 状态。

Check Gate

文档或生命周期产物发生变化时，先验证 audit、plan、ADR、CHANGELOG、输出模板和路由状态。

Review Gate

展示 git status 和 git diff，用户明确批准后才提交、合并、删除分支。

审核输出必须包含什么

审核不是一句“改好了”。它要让用户能判断这批 diff 是否可以进入主分支。

标准分支输出模板位于 skills/dev-branch/templates/output.md。提交或合并审批前使用 Before Approval 形态；只有在用户批准合并且清理完成后，才使用 After Merge 形态。

skills/dev-branch/templates/output.md
Branch: task/YYYYMMDD-short-task-slug

Existing changes before branch:
- ...

Changes made:
- ...

Verification:
- ...

Changelog gate:
- Updated CHANGELOG.md under [Unreleased]
- or Not needed: <reason>

Distill gate:
- Updated CONTEXT/capabilities/ADR/context-map/tests/lifecycle artifacts
- or Not needed: <reason>

Check gate:
- Passed: <command/result>
- or Not needed: <reason>

Review:
- git status --short --branch --untracked-files=all
- git diff

Waiting for approval:
- Say "审核通过" or "可以合并" to let me commit, merge, and clean up.
- Push will not be performed unless separately requested and confirmed.
