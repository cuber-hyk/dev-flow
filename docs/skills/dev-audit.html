Skill

dev-audit

对明确范围做证据化审查，输出可追踪 findings。它负责发现和路由，不负责修复。

流程输出Finding 状态产物

内部流程

先确认审查范围和问题，再低噪音读取事实源，最后按严重程度输出 findings。小审查可留在对话；跨模块、正确性、安全、数据或后续需要修复的审查必须持久化。

输出格式

持久审查必须使用 audit 模板，包含 frontmatter、Scope、Fact Sources、Findings、Verification、Git Visibility、Closeout。Finding 表必须包含 ID、Severity、Status、Evidence、Owner Plan、Branch/Commit、Verification、Closeout。

Finding 状态

只使用 open、planned、resolved、verified。resolved 的原因写入 Closeout，如 fixed、accepted_risk、wont_fix、not_reproducible。Audit 有未关闭 finding 时保持 active。

产物与下一步

持久审查写入 docs/audits/。修复需要计划时交给 /dev-plan skill；实现明确时交给 /dev-branch skill；归档或删除由 /dev-distill skill 的 Audit Closeout Gate 决定。
