技能

dev-split

评估大文件、模块边界和代码放置风险。它不以行数为目标，而是判断职责边界、责任模块、测试边界和后续维护成本。

流程输出状态产物

内部流程

扫描
候选扫描->行数只是信号
判断
读出口/调用方/测试->分类
约束
责任模块->代码放置约束

输出格式

输出必须给出“不拆分、局部整理、延后处理或建议拆分”。同时写明新行为归属、不能继续承载行为的文件、状态和副作用归属、测试归属、外观入口是否仍是入口。

状态转换

defer 必须包含现在不拆的原因、未来重新评估触发条件、非目标和当前任务 guardrail。proposed split 必须等待用户明确批准后才能由 dev-branch 实施。

产物与下一步

结果通常进入 dev-plan 的拆分约束。实现后如果改变模块归属、入口、context-map、capability 或计划/审计生命周期，审核前必须经过 dev-distill 和必要的 dev-check。
