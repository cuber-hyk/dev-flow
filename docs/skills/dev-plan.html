技能

dev-plan

把明确目标转成单一路线、可验证、可交给分支实现的计划。遇到大文件或模块边界风险时，它先引用 dev-split 的结构判断。

流程输出状态产物

内部流程

上下文
读 AGENTS/CONTEXT/context-map->定位事实源
就绪度
确认目标/边界/决策->不清楚则停止提问
计划
3-7 个步骤->每步验证方式

输出格式

最终输出必须包含就绪度、目标、是否持久化、范围、事实源、拆分约束、步骤和验证、验收标准、产物路由、git 可见性和下一步。被决策阻塞时使用阻塞模板，不创建计划文件。

状态转换

计划文件 artifact 只使用 active 和 archived。计划步骤只使用 todo、done、blocked。完成条件是所有非延后步骤为 done、无 blocked、验证结果已记录、关联 audit finding 已更新。

产物与下一步

持久计划写入 docs/plans/YYYY-MM-DD-topic.md。来自审查时必须记录来源审查、覆盖问题和延后问题。涉及大文件、责任模块、状态或副作用边界时，计划必须嵌入 dev-split 的分类和约束。下一步通常是 /dev-branch 技能。
