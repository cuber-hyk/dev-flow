技能边界、文档路由和生命周期规则

这里记录 Dev Flow 的稳定协议。实现者可以用它判断产物应该放哪里、什么时候归档、什么时候写 ADR 或 CHANGELOG。

技能职责 技能详情 Output templates 文档路由 生命周期 ADR Gate CHANGELOG

技能职责

每个技能只负责一个阶段。普通开发可以只使用 dev-plan 和 dev-branch，但底层职责仍然清晰。

技能负责不负责
dev-init创建最小项目记忆结构。推断完整项目知识。
dev-check检查文档路由、生命周期、git 可见性。深度业务审查。
dev-orient低噪声进入仓库上下文。计划、审查、实现或沉淀。
dev-plan内置 orient gate，识别决策点，制定计划。实现或归档知识。
dev-audit内置 orient gate，输出证据化发现。修复问题。
dev-exploratory-review开放式风险发现，建立项目地图与风险地图，只报告真实失败路径。实现修复或评论风格偏好。
dev-branch分支实现、验证、changelog/distill/review gates。静默混入无关改动或自动 push。
dev-changelog维护面向人的发布说明。记录每个 commit 或内部微调。
dev-distill沉淀长期知识并关闭过程产物。重新规划、重新审查或实现。

技能详情

这里按统一模式说明每个技能：先给结论，再说明适用场景、核心流程、边界和下一步。完整执行规则仍以插件内 skills/*/SKILL.md 为准。

dev-init

skills/dev-init/SKILL.md

结论：负责初始化 Dev Flow 的最小记忆结构，但不负责替项目补全所有知识。

适合场景

  • 首次接入 Dev Flow。
  • 补齐缺失的 docs、模板或 agent 指令结构。

核心流程

  • 检查现有项目策略和目录。
  • 只创建缺失结构与模板。
  • 结束后建议运行 dev-check。

不会做

  • 不覆盖既有策略，不推断完整能力文档或 ADR。

dev-check

dev-check

skills/dev-check/SKILL.md

结论：负责验证文档路由和生命周期健康，但不做深度业务审查。

适合场景

  • 初始化后确认结构是否可用。
  • 检查计划、审查、ADR、CHANGELOG 是否归位。

核心流程

  • 运行 docs validation。
  • 识别缺失结构、状态字段和 git 可见性问题。
  • 把问题路由到 init、audit 或 distill。

不会做

  • 不修业务 bug，不替代 dev-audit 或 dev-distill。

dev-init / dev-audit / dev-distill / dev-orient

dev-orient

skills/dev-orient/SKILL.md

结论：负责低噪声进入仓库上下文，但不负责计划、审查或实现。

适合场景

  • 新会话开始前了解项目状态。
  • 识别相关文档、代码入口和产物路由。

核心流程

  • 读取 AGENTS、CONTEXT、context-map 等稳定入口。
  • 只读取任务相关能力文档和代码入口。
  • 推荐继续 plan、audit、branch 或直接小改。

不会做

  • 不写计划、不产出 findings、不沉淀长期知识。

下一步

dev-plan / dev-audit / dev-branch

dev-plan

skills/dev-plan/SKILL.md

结论：负责把目标变成可验证计划，但不负责实现或审查。

适合场景

  • 非平凡功能、修复、重构或文档工作。
  • 审查发现需要转成修复步骤。

核心流程

  • 先运行 Orient Gate。
  • 识别产品、业务、数据、架构等决策点。
  • 决策明确后输出单一路线和验收方式。

不会做

  • 不实现、不审查、不归档知识，不替用户默默决定关键取舍。

下一步

dev-branch

dev-audit

skills/dev-audit/SKILL.md

结论：负责查问题、给证据、写审计报告并路由后续动作，但不负责修复。

适合场景

  • 代码审查、架构审计、文档审计。
  • 正确性、数据流、权限、安全或跨模块风险检查。

核心流程

  • 先定审计边界和问题。
  • 低噪声读取相关事实源。
  • 按严重程度输出 findings，必要时写入 docs/audits/。

不会做

  • 不实现修复，不把审查报告写入 docs/capabilities/。

下一步

dev-plan / dev-branch

dev-exploratory-review

skills/dev-exploratory-review/SKILL.md

结论：负责开放式风险发现，先建立项目地图和风险地图，再报告有真实失败路径的问题。

适合场景

  • 用户不知道问题在哪里，需要检查整个项目、模块、功能、流程或当前分支。
  • 需要多轮验证正确性、数据完整性、安全、并发、性能或用户可见失败风险。

核心流程

  • 先建立 project map 和 risk map。
  • 按 Project Mapper、Risk Prober、Adversarial Verifier、Judge 四轮审查。
  • 只输出有现实触发路径和证据的问题。

不会做

  • 不实现修复，不报告命名、格式或主观偏好问题。

下一步

dev-plan / dev-branch

dev-branch

skills/dev-branch/SKILL.md

结论：负责在隔离分支实现、验证和审核闭环，但不自动提交、合并或 push。

适合场景

  • 计划已明确，需要开始实现。
  • 修复需要完整验证、changelog 和 distill gate。

核心流程

  • 分类 dirty worktree，必要时创建任务分支。
  • 实现并运行验证。
  • 审核前执行 Changelog、Distill 和 Review Gate。

不会做

  • 不自动提交、合并、删除分支或 push；push 需要单独确认。

下一步

dev-check / commit approval

dev-changelog

skills/dev-changelog/SKILL.md

结论：负责维护面向人的 CHANGELOG，但不记录所有 commit。

适合场景

  • 用户、运维、安装、配置、兼容性或安全可见变化。
  • 准备发布或移动 Unreleased 条目。

核心流程

  • 判断是否通过 changelog gate。
  • 保持 ## [Unreleased] 在顶部。
  • 把条目写入 Added、Changed、Fixed 等分类。

不会做

  • 不记录纯内部重构、格式微调、测试-only 或临时过程产物。

下一步

dev-branch review gate

dev-distill

skills/dev-distill/SKILL.md

结论：负责把稳定知识归位并关闭过程产物，但不重新计划、审查或实现。

适合场景

  • 实现或审查后产生稳定事实。
  • 需要归档或删除 active plan/audit。

核心流程

  • 分类知识：capability、ADR、context-map、测试或生命周期产物。
  • 运行 ADR Gate。
  • 关闭计划和审查产物。

不会做

  • 不重新计划、不重新审查、不重新实现。

Output templates

Every skill now has a dedicated final-response template under skills/<skill>/templates/output.md. SKILL.md defines behavior and gates; templates/output.md defines the response shape agents should use at the end of the skill.

SkillTemplateImportant shape
dev-initskills/dev-init/templates/output.mdTarget, created paths, unchanged paths, verification, next step.
dev-checkskills/dev-check/templates/output.mdErrors, warnings, recommendations, validation result, next step.
dev-orientskills/dev-orient/templates/output.mdContext loaded, entry points, fact sources, artifact destinations.
dev-planskills/dev-plan/templates/output.mdReady-to-plan shape plus blocked-by-decisions shape.
dev-auditskills/dev-audit/templates/output.mdScope, findings, evidence, verification, routing.
dev-exploratory-reviewskills/dev-exploratory-review/templates/output.mdScope, project map, risk map, passes, findings, probes.
dev-branchskills/dev-branch/templates/output.mdBefore Approval and After Merge shapes.
dev-changelogskills/dev-changelog/templates/output.mdUpdated, not needed, release prepared, or blocked.
dev-distillskills/dev-distill/templates/output.mdDurable updates plus plan, audit, and ADR closeout.

文档路由

计划、审查、长期事实和决策必须分开存放。capability 只保留当前事实，不存调查过程。

CONTEXT.md

稳定领域词汇和长期业务概念。

docs/ai/context-map.md

任务到 capability、代码入口和产物目录的路由。

docs/capabilities/

当前模块事实、事实源、入口和验证方式。

docs/plans/

仍在驱动当前任务的 active 计划。

docs/audits/

审查报告和未关闭 findings。

docs/adr/

proposed 或 accepted 的长期决策。

生命周期规则

completed 和 distilled 是事件，不是最终状态。被替代内容如果有历史价值就归档，否则删除。

Plan
active->archiveordelete
Audit
active->archiveordelete
Capability
current only->update in place
ADR
proposed->accepted->archived or delete

ADR Gate

ADR 只记录重要、长期、难反悔且有真实取舍的决策。用户不需要每次提醒，dev-distill 必须主动判断。

应该写 ADR

改变事实源、架构路线、数据库迁移策略、长期算法政策、跨模块规则或重大功能取舍。

不应该写 ADR

普通 bug 修复、小 UI 调整、局部重构、一次性审查结论或没有真实备选方案的修正。

状态

只使用 proposed、accepted、archived。不使用 superseded 或 deprecated。

CHANGELOG 规则

更新日志是面向人的发布说明，不是 commit log。dev-branch 在审核前判断是否需要写入。

分类使用场景
Added新增功能、命令、技能、API 或公开能力。
Changed用户可见行为、默认值、安装、配置、兼容性或工作流变化。
Deprecated仍可用但不推荐继续使用的功能、API 或行为。
Removed移除的功能、命令、配置、文件或行为。
Fixed影响用户、业务结果、数据正确性、安装或运行的修复。
Security鉴权、权限、密钥处理或数据暴露相关修复。
