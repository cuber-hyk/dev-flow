Getting Started

从安装到第一个可审核任务

Dev Flow 的接入不要求一次性写完所有项目文档。先创建最小结构，再用真实任务逐步沉淀 capability、ADR 和测试。

安装插件 接入项目 第一个任务 CLI 命令

安装插件

安装方式改为纵向三行，避免命令块被三列布局挤压。Claude、Codex、npm 三种路径各自独立，阅读和复制都更稳定。

Claude Code

添加本地 marketplace 后安装插件。安装后重启 Claude Code，让技能列表刷新到新版本。

Claude Code
claude plugin marketplace add "C:\Users\胡运宽\plugins\cuberhyk-plugins"
claude plugin install cuberhyk-dev-flow@cuberhyk-plugins
claude plugin list

Codex

运行本地安装脚本以注册 `cuberhyk-plugins` marketplace；重启 Codex 后，在 `/plugins` 中安装插件。

Local install
cd C:\Users\胡运宽\plugins\dev-flow
node .\bin\dev-flow.js install

源码本地使用

不发布 npm 时，直接从源码仓库运行本地 CLI。适合个人机器、插件 marketplace 和开发调试。

Source checkout
git clone https://github.com/cuber-hyk/dev-flow
cd dev-flow
node .\bin\dev-flow.js install

接入已有项目

`dev-init` 只创建缺失结构，不覆盖已有项目策略。它负责骨架，真实知识由后续任务沉淀。

1
/dev-init

创建 AGENTS、CONTEXT、context-map、capabilities、plans、audits、ADR 和 CHANGELOG 模板。

2
/dev-check

检查目录、状态字段、gitignore、context-map、CHANGELOG 和潜在 ADR 缺口。

3
/dev-brainstorm、/dev-plan 或 /dev-audit

用真实任务进入上下文；模糊想法先澄清，明确任务再计划，审查任务先输出 findings。

第一个可审核任务

常规功能开发只需要两个入口。计划技能会自动进入上下文；分支技能会在审核前完成验证、更新日志判断和知识沉淀判断。

recommended first task
/dev-brainstorm 我想开发学习统计能力，但还没确认统计口径和展示方式。
/dev-plan 基于已确认的统计口径制定实现计划。
/dev-branch 按计划创建任务分支、实现、验证，并在审核前完成 changelog/distill/check gate。

CLI 命令

正常对话使用技能；CLI 是给 agent 调用的稳定文件操作和校验原语。

命令用途
node .\bin\dev-flow.js install安装到本地 marketplace。
node .\bin\dev-flow.js validate校验插件包结构。
node .\bin\dev-flow.js init-project [dir]作为 `dev-init` 的底层实现，创建缺失文档结构。
node .\bin\dev-flow.js init-design-system [dir]在代表性 UI 审核通过后创建 DESIGN.md 和 design-tokens.json。
node .\bin\dev-flow.js validate-docs [dir]作为 `dev-check` 的底层实现，检查文档路由和生命周期。
