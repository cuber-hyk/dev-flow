Getting Started

从安装到第一个可审核任务

Dev Flow 的接入不要求一次性写完所有项目文档。先创建最小结构，再用真实任务逐步沉淀 capability、ADR 和测试。

安装插件 接入项目 第一个任务 CLI 命令

安装插件

安装方式改为纵向三行，避免命令块被三列布局挤压。Claude、Codex、npm 三种路径各自独立，阅读和复制都更稳定。

Claude Code

添加本地 marketplace 后安装插件。安装后重启 Claude Code，让技能列表刷新到新版本。

Claude Code
claude plugin marketplace add "C:\Users\胡运宽\plugins\cuberhyk-plugins"
claude plugin install cuberhyk-dev-flow@cuberhyk-plugins
claude plugin list

Codex

运行本地安装脚本，或在 `/plugins` 中选择 `cuberhyk-plugins` marketplace 后安装。

Local install
cd C:\Users\胡运宽\plugins\dev-flow
node .\bin\dev-flow.js install

npm 发布后

公开发布后，安装流程可以收敛为一个 `npx` 命令，适合跨机器快速接入。

npx
npx cuberhyk-dev-flow install

接入已有项目

`dev-init` 只创建缺失结构，不覆盖已有项目策略。它负责骨架，真实知识由后续任务沉淀。

1
/dev-init

创建 AGENTS、CONTEXT、context-map、capabilities、plans、audits、ADR 和 CHANGELOG 模板。

2
/dev-check

检查目录、状态字段、gitignore、context-map、CHANGELOG 和潜在 ADR 缺口。

3
/dev-plan 或 /dev-audit

用真实任务进入上下文，逐步生成能力文档和稳定事实。

第一个可审核任务

常规功能开发只需要两个入口。计划技能会自动进入上下文；分支技能会在审核前完成验证、更新日志判断和知识沉淀判断。

recommended first task
/dev-plan 开发学习统计的连续学习天数。请先进入上下文、识别统计口径决策点，再制定计划。
/dev-branch 按计划创建任务分支、实现、验证，并在审核前完成 changelog/distill/check gate。

CLI 命令

正常对话使用技能；CLI 是给 agent 调用的稳定文件操作和校验原语。

命令用途
cuberhyk-dev-flow install安装到本地 marketplace。
cuberhyk-dev-flow validate校验插件包结构。
cuberhyk-dev-flow init-project [dir]作为 `dev-init` 的底层实现，创建缺失文档结构。
cuberhyk-dev-flow validate-docs [dir]作为 `dev-check` 的底层实现，检查文档路由和生命周期。
